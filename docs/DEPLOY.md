# Deploy guide

This guide takes you from an empty Linux server to a public HTTPS site with
the app running. Follow it in order. Each step says what to check before you
move on.

> **Not yet done**
>
> - The live deploy has never been run end to end. Treat every step as
>   untested until you run it and check the result.
> - CI does not boot the Compose stack. It runs unit tests against Postgres
>   and builds the frontend. Nothing checks that the containers start.
> - `docker-compose.yml` forwards `VAPID_*` and `LLM_KEY_SECRET`. It still does
>   not forward the two rate-limit settings, so those stay at their defaults
>   unless you add them. See [Environment variables](#environment-variables).
> - CI uses Postgres 17. The Compose file uses Postgres 16.

## What you get

Five containers, defined in [docker-compose.yml](../docker-compose.yml):

| Service | Image | Port | Role |
|---|---|---|---|
| `edge` | `caddy:2-alpine` | 80, 443 public | Terminates TLS, gets the certificate, forwards to `web` |
| `web` | nginx, built from `frontend/` | internal | Serves the PWA, proxies `/api/` to `api` |
| `api` | FastAPI, built from `backend/` | internal | Runs migrations on boot, then serves the API |
| `db` | `postgres:16` | internal only | Data, in the `pgdata` volume |
| `redis` | `redis:7-alpine` | internal only | Cache and coordination |

Only `edge` publishes ports. `db` and `redis` have no published port, so the
internet cannot reach them.

A PWA needs HTTPS to install and to receive push. Plain HTTP works for a
local test only.

## 1. Prerequisites

You need these before you start.

- **A Linux server with a public IP.** Any small VPS works. Ubuntu or Debian
  is the easiest path.
- **Docker Engine and the Compose plugin.** Install from
  <https://docs.docker.com/engine/install/>. Check with:
  ```bash
  docker --version
  docker compose version
  ```
- **Git and OpenSSL.** Usually preinstalled. Check with `git --version` and
  `openssl version`.
- **A domain you control.** You need access to its DNS settings.
- **Open inbound ports 80 and 443** in the server firewall and the cloud
  provider's panel. Let's Encrypt issues the certificate over port 80.
- **Keys for the features you want.** Each one is optional. A blank key turns
  off its feature and the app says so.

| Key | Needed for | Where to get it |
|---|---|---|
| LLM API key and base URL | Chat | Your provider: OpenAI, OpenRouter, or MiniMax |
| `POLLEN_API_KEY` | Real pollen readings | data.go.kr, search for 꽃가루농도위험지수 (KMA) |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | Hospital finder | developers.naver.com, Search API, Local |
| VAPID key pair | Web push | Generated by you (step 3) |

Air quality and weather use Open-Meteo, which needs no key.

## 2. Point the domain at the server

Create a DNS A record for your domain (for example `allergy.example.com`)
pointing at the server's public IP. Wait until it resolves:

```bash
dig +short allergy.example.com
```

The answer must be your server's IP. If it is not, wait and check again.
Caddy cannot get a certificate for a name that does not resolve yet. It
retries on its own once DNS catches up.

## 3. Get the code and write the environment file

```bash
git clone https://github.com/haksenguz/cohort-1-pollen-today-project.git
cd cohort-1-pollen-today-project
git checkout feat/ismoiljon

cp .env.example .env
chmod 600 .env
```

Open `.env` and fill in the required values. Generate the secrets as shown.

```bash
openssl rand -hex 32   # JWT_SECRET
openssl rand -hex 32   # LLM_KEY_SECRET, if you set it (see table)
```

Generate the VAPID pair after the first build (step 5 has the command). The
script needs the built image.

Save the file. Then check it:

```bash
grep -E '^(PUBLIC_ORIGIN|JWT_SECRET|POSTGRES_PASSWORD)=' .env | cut -c1-40
```

Each line must show a value. `JWT_SECRET` must not be `change-me`.

### Environment variables

Compose reads the root `.env` only for `${...}` substitution in
`docker-compose.yml`. A variable reaches a container only when the Compose
file lists it under that service's `environment:`. The table notes which
variables are forwarded.

| Name | Required | Forwarded to `api` | Purpose | How to set it |
|---|---|---|---|---|
| `PUBLIC_ORIGIN` | Yes | Yes (`api`, `web` build, `edge`) | The site's origin. Baked into the frontend bundle at build time. Caddy uses it as the site address. | `https://allergy.example.com`, no trailing slash |
| `JWT_SECRET` | Yes | Yes | Signs login tokens. Anyone with this value can forge a login. | `openssl rand -hex 32`. At least 32 characters. Not an example value. |
| `POSTGRES_USER` | Yes | Yes (`db`, `api`) | Database user | Your choice, for example `allergy` |
| `POSTGRES_PASSWORD` | Yes | Yes (`db`, `api`) | Database password. Compose refuses to start without it. | A long random value |
| `POSTGRES_DB` | Yes | Yes (`db`, `api`) | Database name | For example `allergy_ai` |
| `ENVIRONMENT` | No | Yes | Defaults to `production`. Turns on the boot guard. | Leave as `production` |
| `CORS_ORIGINS` | No | Yes | Extra origins allowed to call the API from a browser. The app adds `PUBLIC_ORIGIN` itself. | Leave as `[]` for a normal deploy |
| `OPENAI_API_KEY` | No | Yes | Chat model key. Blank disables chat. | Your provider's key |
| `OPENAI_BASE_URL` | No | Yes | Provider endpoint. Blank means OpenAI. | MiniMax `https://api.minimax.io/v1`, OpenRouter `https://openrouter.ai/api/v1` |
| `OPENAI_MODEL` | No | Yes | Model id. Blank uses `gpt-4o-mini`. | Must match the provider. MiniMax and OpenRouter use different ids. |
| `POLLEN_API_KEY` | No | Yes | KMA pollen serviceKey. Blank serves a flagged sample. | data.go.kr key |
| `NAVER_CLIENT_ID` | No | Yes | Hospital finder | Naver developer app |
| `NAVER_CLIENT_SECRET` | No | Yes | Hospital finder | Naver developer app |
| `OPERATOR_NAME` | Yes for real users | Yes | Operator named in the privacy policy. Blank means the policy says no operator is named. | Your business name |
| `OPERATOR_REGISTRATION_NUMBER` | Yes for real users | Yes | 사업자등록번호 in the policy | Your number |
| `PUBLIC_BIND` | No | No (used by `edge` port mapping) | Interface for ports 80 and 443. Default `0.0.0.0`. | Leave as default |
| `VAPID_PUBLIC_KEY` | For push | Yes | Web push public key | Step 5 |
| `VAPID_PRIVATE_KEY` | For push | Yes | Web push private key | Step 5 |
| `VAPID_SUBJECT` | For push | Yes | Contact for push services, `mailto:` form | `mailto:you@example.com` |
| `LLM_KEY_SECRET` | No | Yes | Encrypts users' own LLM keys. Blank uses `JWT_SECRET`. | `openssl rand -hex 32` |
| `CHAT_RATE_LIMIT_PER_MINUTE` | No | **No, add it** | Chat requests per user per minute. Default 20. | Integer |
| `AUTH_RATE_LIMIT_PER_MINUTE` | No | **No, add it** | Register and login attempts per IP per minute. Default 10. | Integer |
| `DEV_SETTINGS_ENABLED` | Must be off | Set to `false` in Compose | Turns on an unauthenticated route that reads and writes provider keys. | Never set it to true in a deploy. |
| `DEMO_MODE` | Must be off | Not set | Resolves requests without a token to a demo user. | Never set it in a deploy. |

Settings you must not set in `.env`: `DATABASE_URL` and `REDIS_URL`. Compose
builds them from the values above.

To forward a "add it" variable, add a line under the `api` service's
`environment:` block in `docker-compose.yml`, for example:

```yaml
      VAPID_PUBLIC_KEY: ${VAPID_PUBLIC_KEY:-}
```

Do the same for each variable you need. Then run `docker compose up -d` again.

`DEV_SETTINGS_ENABLED` and `DEMO_MODE` are the two settings that must stay
off. The app refuses to start in production if either one is on.

## 4. Build the images

```bash
docker compose build
```

The first build pulls base images and compiles the frontend. It takes a few
minutes. The `web` build fails with `VITE_API_BASE_URL build arg is required`
if `PUBLIC_ORIGIN` is empty. Fix `.env` and build again.

## 5. Generate the VAPID keys (optional, for push)

Skip this step if you do not want push notifications.

```bash
docker compose run --rm api python scripts/gen_vapid_keys.py
```

The script prints a public and a private key. Copy them into `.env` as
`VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`, and set `VAPID_SUBJECT` to a
`mailto:` address you read. Then forward the three variables as described
above, and run `docker compose up -d` again.

Without these keys, alerts still save. Nothing is pushed to the phone.

## 6. Start the stack

```bash
docker compose up -d
docker compose ps
```

Every service should show `running`, and `db` and `redis` should show
`healthy` after a few seconds. If one shows `restarting`, go to
[Troubleshooting](#troubleshooting).

Watch Caddy get the certificate:

```bash
docker compose logs -f edge
```

Look for a line that says the certificate was obtained. Press Ctrl+C to stop
following the log.

## 7. Run the migrations

You do not need to run migrations by hand. The `api` container runs
`alembic upgrade head` each time it starts (see `backend/entrypoint.sh`). A
second run does nothing when the schema is current.

To check the schema version:

```bash
docker compose exec api alembic current
```

To run the upgrade yourself and see its output:

```bash
docker compose exec api alembic upgrade head
```

Do not run migrations from several API replicas at once. Run one replica.

## 8. Put HTTPS in front of the app

The stack already includes HTTPS. The `edge` container runs Caddy with
[deploy/Caddyfile](../deploy/Caddyfile). It reads `PUBLIC_ORIGIN` as its site
address, gets a certificate from Let's Encrypt, redirects HTTP to HTTPS, and
forwards everything to `web`. You do not install Caddy on the host.

The relevant part of the file looks like this:

```
{$SITE_ADDRESS} {
    reverse_proxy web:80 {
        flush_interval -1
    }
    header { ... }
}
```

`flush_interval -1` keeps chat streaming live. Remove it and chat answers
arrive all at once.

Certificates and account data live in the `caddy_data` volume. Keep that
volume. Deleting it makes Caddy request new certificates on the next start,
and Let's Encrypt limits how many it issues.

Do not put a second reverse proxy in front of `edge` unless you have a
reason. This guide does not cover that setup.

## 9. Smoke test

Run these checks in order. Stop at the first failure and read
[Troubleshooting](#troubleshooting).

**Health, over TLS:**

```bash
curl -sS https://allergy.example.com/health
```

Expected: `{"status":"ok","service":"allergy-ai-backend"}`

**The site:** open `https://allergy.example.com` in a browser. The login page
loads. Register an account. Accept the sensitive-data consent when asked.

**Browser console:** open developer tools. There must be no CORS errors and no
mixed-content warnings.

**Live chat check.** This script registers a test account, holds a two-turn
Korean conversation, and checks the emergency verdict against the rule
engine. It spends real model tokens and writes a test user. Run it on purpose,
not on every deploy:

```bash
docker compose exec -e VERIFY_BASE_URL=https://allergy.example.com api \
  python scripts/verify_live_chat.py
```

Exit code 0 means it passed. Any other code means a step failed. The script
prints which one.

**Live pollen check.** This calls KMA with the key in the container and prints
the provider's answer:

```bash
docker compose exec api python scripts/verify_live_pollen.py
```

Read the result in season. Tree pollen comes from March to June. Weeds come
from August to October. An empty result in January is expected.

**Environment endpoint:**

```bash
curl -sS https://allergy.example.com/api/environment/current
```

If `pollen_is_sample` is `true`, `POLLEN_API_KEY` is blank or rejected.

## 10. Back up Postgres

Make a backup before every update. Make one on a schedule too. This guide does
not set up scheduled backups.

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  | gzip > "backup-$(date +%F-%H%M).sql.gz"
```

Store the file off the server. A backup on the same disk does not protect you
from losing the disk.

To restore into a stack with an empty database:

```bash
gunzip -c backup-2026-11-18-0900.sql.gz \
  | docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Test the restore on a second server before you need it.

## 11. Update the app

```bash
cd cohort-1-pollen-today-project
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  | gzip > "pre-update-$(date +%F-%H%M).sql.gz"

git pull
docker compose up -d --build
docker compose logs --tail=50 api
```

The `api` container runs new migrations on boot. Read its log to confirm the
upgrade finished before you trust the new version.

Changing `PUBLIC_ORIGIN` requires a rebuild of `web`, because the value is
baked into the bundle. `docker compose up -d --build` does that.

## 12. Roll back

Rolling back the code is quick. Rolling back the schema is not.

1. Find the commit you want to return to: `git log --oneline -n 10`.
2. Check out that commit: `git checkout <commit>`.
3. Rebuild and restart: `docker compose up -d --build`.

If the newer version added a migration, the old code still runs on the newer
schema. The `api` container also runs `alembic upgrade head` when it starts,
so it will not remove that migration. Before you go back, read the
`downgrade()` function in the migration file. If it can undo the change, run
it with:

```bash
docker compose exec api alembic downgrade <revision>
```

Restore the backup from step 11 if the downgrade is not safe or not
possible. Restoring loses any data written after the backup.

## Troubleshooting

### The API container restarts in a loop

Read the log first:

```bash
docker compose logs --tail=100 api
```

| Log text | Cause | Fix |
|---|---|---|
| `Refusing to start in production mode` | A readiness check failed. The log lists each reason. | Fix the listed setting: a short or example `JWT_SECRET`, or `DEV_SETTINGS_ENABLED` or `DEMO_MODE` set to true. |
| `could not connect to server` or `connection refused` on `db` | Postgres not ready, or wrong credentials | Check `docker compose ps db`. Check `POSTGRES_*` values match the ones the database was created with. |
| `alembic` traceback | A migration failed | Read the last error. Do not drop tables to get past it. Restore the backup and report the error. |
| `password authentication failed` | `POSTGRES_PASSWORD` changed after the volume was created | The volume keeps the old password. Set the old value back, or reset the volume. Resetting deletes all data. |

Changing `POSTGRES_PASSWORD` in `.env` does not change a password that already
exists in the `pgdata` volume.

### The browser shows a CORS error

The site and the API run on one origin, so CORS should not fire. If it does:

- Check that you open the site on the exact domain in `PUBLIC_ORIGIN`. A
  `www.` prefix or `http://` makes a different origin.
- Check that `PUBLIC_ORIGIN` has no trailing slash.
- Rebuild `web` after changing `PUBLIC_ORIGIN`: `docker compose up -d --build`.

### Chat answers "setup problem" or 400 `output_parse_failed` (gpt-oss)

The app shows `misconfigured` when the provider rejects the request. It shows
`malformed` when the model's output cannot be parsed. A gpt-oss response with
`output_parse_failed` is counted as `malformed`, so the user sees "could not
read the answer, try again." Retrying usually works. If it keeps failing:

- Check the log for `output_parse_failed`:
  `docker compose logs api | grep -i output_parse_failed`
- Confirm `OPENAI_BASE_URL` and `OPENAI_MODEL` come from the same provider.
  A MiniMax model id sent to OpenRouter returns 404.
- A key sent to the wrong host returns 401 "Missing Authentication header".
  That message looks like a missing key. It is a mismatched host.

### Certificate errors when the API calls providers

Symptoms: weather, pollen, or Naver calls fail with `CERTIFICATE_VERIFY_FAILED`
in `docker compose logs api`. This usually happens on a network that
re-signs TLS (a corporate proxy or an antivirus).

`backend/app/main.py` loads `truststore`, which uses the operating system's
certificate store. Inside the Linux container, that store is the one in the
image, not the host's. A corporate root certificate therefore has to be added
to the image. Add it in `backend/Dockerfile`, then rebuild. This is how
`truststore` works, but this guide has not tested that fix.

### Caddy never gets a certificate

```bash
docker compose logs edge
```

Common causes:

- DNS does not point at this server yet (step 2).
- Port 80 or 443 is blocked by the firewall or the cloud panel.
- Another program already uses port 80 or 443. Stop it, then run
  `docker compose up -d` again.

Caddy keeps retrying in the background. It recovers once the cause is fixed.

### Push does not arrive

- Check that `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_SUBJECT` are
  forwarded to `api` (see [Environment variables](#environment-variables)).
- Check `GET /api/push/vapid-key`. It returns `null` when push is off.
- Push needs HTTPS and a permission grant from the user.

### No pollen data, or `pollen_is_sample` is true

- `POLLEN_API_KEY` is blank or rejected. Run `verify_live_pollen.py`.
- Season matters. Off-season, empty results are correct.

### The site loads but the PWA does not install

Installation needs HTTPS and a valid certificate. Check the address bar for a
lock icon. A certificate warning means step 8 is not finished.

## Operational notes

- **One API replica only.** The alert scheduler runs inside each API process.
  Two replicas would send duplicate alerts and run migrations twice.
- **Rate limits are per process.** Chat and login counters live in memory.
  A restart clears them.
- **Logs.** `docker compose logs -f <service>`. Logs go to the container's
  standard output. This guide does not set up log rotation or a log service.
- **Restart policy.** Every service restarts unless stopped
  (`restart: unless-stopped`). A server reboot brings the stack back.
